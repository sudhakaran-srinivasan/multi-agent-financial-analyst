Research Agent Architecture

An autonomous investment research agent for one stock at a time. The model decides which data to gather and writes the thesis; Python checks every number, computes the signals, decides when to retry, and decides when an analysis is good enough. The names below are the names in the code.

News workflow: prompt chaining and routing

This is the get_news_insights tool. It runs as a fixed chain, so code decides the order. Each article gets one label, and the label picks exactly one specialist.

What the model may do

  • Label an article: earnings, market, general or irrelevant.
  • Extract short facts from the article.
  • Summarize those facts and give a sentiment.

What Python checks

  • The label is one of the four, or the article is skipped and counted.
  • Every number in the facts and summary appears in the article.
  • Sentiment is valid; the summary is length-capped.
  • Article text sits in the user message only.

Evaluator-optimizer loop

A second reader with a checklist. The judge gives scores; it never decides. Python applies the verdict rule, and a failing draft goes back through synthesis with the judge's notes.

The six criteria

  • evidence_support: every claim backed by a fact
  • numeric_accuracy: numbers match the raw tool data
  • stance_consistency: the stance follows the evidence
  • risk_coverage: real risks, traceable to the data, plus the gaps
  • confidence_calibration: honest given the gaps
  • source_quality: evidence has named sources

The verdict rule

  • Each criterion is a whole number from 1 to 5, described at 1, 3 and 5.
  • Pass: mean ≥ 4.0 and no score below 3.
  • Any critical issue forces a revision, whatever the scores.
  • Ties keep the earlier draft; a revision must be strictly better.

Failure policy, known limits, next steps

Failure policy

  • Setup problem (missing API key): raises.
  • Bad ticker or not a stock: a normal result, later stages skipped.
  • Failed fetch: raises, so the trace shows ok=False and reflection can retry.
  • Later-stage crash: recorded in stage_errors; the run returns partial results.
  • Unusable model reply in synthesis: rule-based analysis at low confidence.

Known limits

  • The same model writes and judges by default.
  • The judge is not yet calibrated against human ratings.
  • The number check catches invented numbers, not invented claims.
  • Risks are free text; they are not yet source-linked like evidence.
  • Finnhub's free news feed is capped and noisy; news sentiment leans positive.
  • The news step makes many sequential model calls per ticker.
